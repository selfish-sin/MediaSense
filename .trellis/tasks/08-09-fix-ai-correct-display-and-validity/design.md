# AI 校正：数据流分析与设计方案

> 2026-08-09 | task 08-09-fix-ai-correct-display-and-validity | Design 阶段

## 一、功能现状

AI 校正（`ai_correct`）是任务流水线里的可选步骤，用云端 LLM 修正 ASR 转录文本的同音错字、专名、标点、断句。

- 开关：`HomeView.vue:1421` `settings.advancedOptions.ai_correct`，**默认 false**。
- 模型：`ai_correct_model` 默认空串，UI 无选模型入口（恒用主模型）。
- 流水线顺序：`Step1 下载/转录 → Step1.5 校正 → Step2 预览 → Step3 总结`（`main.py`）。
- 校正函数：`ai_processor.py:488 correct_transcript`，真 LLM 调用，80k 字符分块。

**问题汇总**：
- ① **标签错**（组合 C/G/H）：`do_summary=False` 时 `result_text` 存的是转录/校正文本，但结果页 tab 标签固定写"AI 总结"，误导。
- ② **校正不可见**（组合 D/E/F/G/H）：校正后文本写回 txt，但 ResultView 从不读 `job.files`，无法单独查看校正结果或对比原文。校正"做了等于没做"（用户看不到效果）。
- ③ **预览覆盖校正无回退**（组合 E）：用户在预览编辑会覆盖校正后文本，且校正不重跑。校正原文在 `txt_raw`，但既不展示也不可用于重新校正。

## 四、设计选项

### 展示问题（①②③）

**选项 1：ResultView 加「转录文本」tab + 原文/校正切换**（用户初选）
- 新增第三个 tab「转录文本」，读 `job.files.txt`（校正后）经 `/download/view` 展示；若 `job.files.txt_raw` 存在则加「原文/校正」切换。
- `do_summary=False` 时默认切到「转录文本」tab，tab 标签动态化（有总结显示"AI总结"，无则隐藏）。
- 复用现成 `/download/view?path=` 端点（path-based，前端 `jobsApi.view` 已封装）。
- 优点：校正效果可见、可对比；不改 DB。
- 缺点：`/download/view` 返回 FileResponse，前端要 fetch 文本内容（当前 api.js 的 view 可能返回 blob，需确认/加 text 端点）。

**选项 2：DB 加 `corrected_text` 字段分流**
- 校正结果单独存列，`result_text` 只放总结。前端加校正面板。
- 优点：数据模型最干净。
- 缺点：需 DB 迁移；校正文本可能很大（80k+），存 DB 列不理想；老任务无此字段。

**选项 3：只改标签**（最小）
- `do_summary=False` 时 tab 标签从"AI总结"改"转录文本"。
- 优点：改动极小。
- 缺点：不解决②③（校正不可见、预览覆盖）。

### 有效性加固

**方案 A：全面加固**（用户初选）
1. 时间戳完整性校验：校正前后统计 `[MM:SS]` 数量，不一致则该 chunk 标记失败 + 回退原文 + 告警。
2. 长度异常检测：校正后长度变化超阈值（如 ±30%）则标记可疑。
3. 静默回退改显式：失败 chunk 在返回结果里标记，前端/日志可见。
4. 分块按时间戳/换行边界切：不在标记中间断。
5. 补单元测试：mock `_call_ai`，覆盖成功/部分失败/时间戳丢失/空输入。

**方案 B：只加时间戳校验 + 测试**（折中）
- 只做第 1、5 项，其余记 backlog。

## 五、待用户确认

1. **展示方案**：选项 1（加 tab+切换，不改 DB）是否 OK？还是倾向选项 2（DB 分流）？
2. **`/download/view` 返回格式**：需确认前端能否拿到文本（若返回 blob 需加一个返回 text 的端点，或前端读 blob.text()）。这点我会在实现时确认，不阻塞设计决策。
3. **预览覆盖校正（问题③）**：是否要在用户编辑预览后提示"你的编辑会覆盖校正结果"？还是保持现状（编辑优先）？
4. **有效性方案**：方案 A（全面）还是 B（折中）？
5. **`ai_correct_model` 无 UI 入口**：要不要这次顺手加一个模型选择器？还是后续单独处理？

## 六、影响范围（依方案定）

- 展示选项 1：`ResultView.vue`（加 tab + 文件读取）、`api.js`（可能加 text 端点封装）、可能 `download.py`（加返回 text 的端点）。
- 有效性方案 A：`ai_processor.py`（校验/分块/失败标记）、`main.py`（告警）、`test_ai_processor.py`（测试）。
- 不改 DB schema（选项 1）。
