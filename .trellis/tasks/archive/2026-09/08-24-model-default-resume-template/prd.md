# 模型默认 / 失败重试 / 新增模板优化

## Goal

用户提出的三点改进，围绕「AI 模型选择」与「失败恢复」的日常体验：

1. 模型管理页支持设置「默认模型」，之后各处的模型选择器（工作台/重新总结）自动默认到它，不用每次手动切换。
2. AI 总结偶发失败时，允许对**已失败**的任务直接「重新总结」——只重跑最后的 AI 步骤（不重新下载、不重新转录）。同时修复本次总结失败的根因。
3. 优化「新增模型」的表单模板：提供常见服务商快捷模板、从接口拉取模型列表后一键添加，减少手填字段。

## Requirements

### R1 默认模型设置
- 模型管理页每个模型行可「设为默认」，当前默认模型有可见标识（如标签）。
- 默认模型持久化到后端数据库；`GET /api/models` 返回的有效默认值来自数据库（未设置时回退 `config.DEFAULT_MODEL`）。
- 新增接口 `POST /api/models/default`（body `{"key": ...}`），校验模型存在后保存。
- 前端各处模型选择器（HomeView 工作台、ResummarizeDialog）初始选中默认模型；用户手动选过或任务恢复时不得被覆盖。
- 「按字数自动推荐模型」逻辑不得再覆盖用户设置的默认模型（仅对未设置过默认/未手选的旧行为生效）。

### R2 失败任务重试总结（仅重跑 AI 步骤）
- 后端 `POST /api/jobs/{id}/summarize` 允许 `failed`（以及 `completed`）状态的任务重新总结；前提是任务保留有效转录文本（`files.txt` 存在且非空）。
- 失败任务在结果页可见「重新总结」入口（带失败原因提示），并提示无需重新下载/转录。
- 重新总结结果不再把 `[处理失败: ...]` 哨兵串当正常结果写盘（与 `main.py` 的契约检查对齐）。
- 根因修复：流式响应 chunk 的 `choices` 为空数组时不再抛 `list index out of range`（`backend/services/ai_processor.py`），`routers/models.py` 测试接口同样加固。

### R3 新增模型模板优化
- 添加模型弹窗提供常见服务商快捷模板（DeepSeek / 阿里云百炼 / OpenAI / 智谱 GLM / 硅基流动 / 本地 Ollama），点击预填端点。
- 「从端点获取模型列表 → 点添加」一步完成保存（复用弹窗里已填的 endpoint/api_key，不再弹回表单二次提交）。
- Key/名称可自动派生（由 model_id 生成）；端点缺 `/chat/completions` 时自动补全。
- 编辑模型时同样享受端点补全。

## Acceptance Criteria

- [ ] 模型管理页可设默认模型；重启后端后默认模型保持；未设置时回退 config 默认值。
- [ ] 工作台/重新总结弹窗的模型选择器默认选中数据库默认模型。
- [ ] 失败（AI 总结阶段）的任务在结果页可直接「重新总结」，且只调用 AI 步骤（无下载/转录日志）。
- [ ] `choices: []` 的流式 chunk 不再导致总结失败（回归测试覆盖）。
- [ ] 新增模型流程：点快捷模板 → 填 key/API Key → 或从接口拉列表一键添加，均能成功保存。
- [ ] 后端 pytest 全绿；前端 vitest 全绿；静态资源重新构建。
